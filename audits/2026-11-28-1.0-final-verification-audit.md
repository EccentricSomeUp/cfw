## Delta review notes

- `cfw_server_step` dispatch: conn pollset registrations carry the conn
  as token on all four backends (epoll, kqueue, poll, WSAPoll —
  `events[].token` populated in each `*_wait`). Conns are never freed
  during dispatch (only `dead`-marked; `cfw_server_sweep` runs before
  wait and after dispatch), so snapshotted tokens cannot dangle.
  Listener/wakeup registrations are filtered by handle before the
  token cast; accept-path frees only touch not-yet-registered conns.
  `cfw_server_mark_expired` marks deadline-expired conns dead before
  dispatch — fail-closed and consistent with "expired connections are
  never serviced"; conns expiring mid-wait are now skipped rather
  than serviced once, which is the documented invariant.
- `cfw_addr_resolve_all`: two-pass getaddrinfo enumeration with
  overflow-checked allocation; `filled <= count` on partial
  `cfw_addr_store` failure; NULL-safe `cfw_addr_list_free`; public
  `cfw_addr_resolve` contract preserved (first result). Blocking
  resolver use is unchanged from the previous single-result call and
  remains connection-setup-only per the header contract.
- `cfw_hc_ensure_conn`: iterates every address per family in
  IPv4-then-IPv6 order; inner loop breaks only on
  `TIMEOUT`/`UNAVAILABLE` so connect-refused (`CFW_ERROR_IO`) falls
  through to the next A/AAAA record as intended; the shared deadline
  still bounds every attempt; failed attempts clean up fd + pollset
  registration inside `cfw_hc_connect_fd`.
- WSAPoll `count == 0` wait sleeps for the computed timeout (or
  `INFINITE` for NULL deadline) — matches epoll/poll semantics;
  `timeout_ms` is clamped to `INT32_MAX` upstream.
- `cfw_http1_pending_span` NULL-data fix and `fs.c`/`tls.c`
  portability guards are behavior-preserving off their target
  platforms.
