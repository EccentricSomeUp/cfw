# Audit: 1.0 candidate — full catalog pass

- Date: 2026-11-27
- Auditor: Devin (agent)
- Commit: `9a87868` (main)
- Category: all (`docs/security/audit-catalog.md`)
- Scope: entire public API and implementation (`include/cfw/*.h`,
  `src/cfw/*.c`, `src/cfw/private/*.c`, `tests/`, build/CI/release
  configuration). Supersedes the readiness pass in
  `2026-11-26-1.0-readiness-audit.md`, which predates Windows
  networking/TLS, the WebSocket client, the public socket/pollset
  APIs, the fuzz-target suite, the HTTP client hardening (ADR 0078),
  and the ThreadSanitizer preset.

## Goals

- Verify every catalog area against the tree intended for `1.0.0`.
- Confirm the 1.0 blockers from the prior readiness verdict are
  resolved or dispositioned.
- Deep-review the newly landed HTTP client session/redirect/retry/
  streaming engine, the `cfw_server_stop` cross-thread fix, and the
  release/CI matrix changes.

## Method

- Line-level review of `src/cfw/http_client.c` (new ~2000-line
  exchange engine), `src/cfw/server.c` shutdown path, redirect
  resolution (RFC 3986 merge + dot-segment removal), TLS session
  save/restore, and retry/stale-connection logic.
- Review of `CMakePresets.json`, `cmake/cfw_compile_options.cmake`,
  `.github/workflows/ci.yml`, `.github/workflows/release.yml`,
  `scripts/cfw-release.sh`, and `docs/api-stability.md` for
  release-gate correctness.
- Local verification on Linux: debug, release, sanitizers (ASan +
  UBSan), shared, debug-tls, tsan (Clang), and fuzz preset builds;
  full `ctest` per preset; libFuzzer smoke on
  `cfw_fuzz_http_client` (33k execs, no crashes); corpus replay under
  ASan/UBSan.

## Findings this pass

| ID | Severity | Location | Summary | Disposition |
|----|----------|----------|---------|-------------|
| A-001 | Medium | `src/cfw/http_client.c` `cfw_hc_ensure_conn` | TLS setup or authority-bind failure after a successful connect left `conn_open` set while `auth_host` still described the previous authority — a later perform could reuse a socket bound to the wrong authority | Fixed (`9a87868`): failures past connect now drop the connection; `conn_close` clears the binding |
| A-002 | Low | `src/cfw/http_client.c` `cfw_hc_validate_request` | `header_count > 0` with `headers == NULL` dereferenced NULL; huge `header_count` could overflow the generated-headers allocation | Fixed (`9a87868`): both rejected with `CFW_ERROR_INVALID_ARGUMENT`; regression test added |
| A-003 | Low | `src/cfw/http_client.c` redirect path | Unresolvable `Location` returned the 3xx head but an empty body (redirect-hop bodies were discarded before resolvability was known) | Fixed (`31079b3`): hop bodies now buffer into the hop buffer — discarded on follow, preserved when the 3xx is final |
| A-004 | Info | `tests/unit/test_loopback.h` | Missing `<string.h>` — implicit `memcmp` declaration is an error under Clang, which would fail the CI fuzz job | Fixed (`e7a2591`) |
| A-005 | Info | `tests/CMakeLists.txt` fuzz block | libFuzzer targets were not coverage-instrumenting the `cfw` library (~57 vs ~6000 counters); ASan could not see inside library code | Fixed (`e7a2591`): `cfw` compiles with `fuzzer-no-link,address,undefined` on Clang fuzz builds |
| A-006 | Info | `src/cfw/server.c` `cfw_server_stop` | Cross-thread shutdown mutated pollset/server state concurrently with the event loop (found by TSan) | Fixed (`f016f6c`): atomic `stopping`, deferred listener unregister, accept refuses once stopping |

No critical or high findings remain open. All findings above are
fixed on `main`.

## API/ABI freeze review

- Public headers reviewed for append-only compatibility: the only
  struct growth since the freeze decision is `cfw_http_client_request_t`
  appended fields (ADR 0078), permitted by `docs/api-stability.md`.
- New public types added this cycle are opaque
  (`cfw_http_client_session_t`), matching the "prefer opaque types"
  rule.
- `CFW_ABI_VERSION` stays `1`, documented as the ABI frozen at 1.0.0.
- Enum additions (`CFW_HTTP_STATUS_SEE_OTHER`,
  `TEMPORARY_REDIRECT`, `PERMANENT_REDIRECT`) are additive.
- Post-1.0 roadmap items (request-ID hooks, validation helpers,
  security-headers middleware, observability, supply-chain work) were
  evaluated and correctly remain staged post-1.0: every one is
  implementable as additive minor-release surface, so none must land
  before the freeze.
