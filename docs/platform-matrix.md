# Platform matrix

This matrix records the intended support targets and the status of platform
abstractions. "Implemented" means the boundary exists and is unit-tested on
the development host; "designed" means the contract is recorded in an ADR but
not yet implemented; "planned" means no contract exists yet.

## Targets

| Platform | Status | Notes |
| --- | --- | --- |
| Linux (glibc/musl) | Primary | `clock_gettime`, `getrandom`, `epoll`; the primary CI/dev-verified target |
| macOS | POSIX-compatible | `clock_gettime`, `arc4random_buf`, `kqueue` backend (ADR 0052); verified on macOS CI |
| FreeBSD/OpenBSD/NetBSD | POSIX-compatible | `clock_gettime`, `arc4random_buf`, `kqueue` backend (ADR 0052); FreeBSD verified on CI (debug preset via `vmactions/freebsd-vm`); OpenBSD/NetBSD not yet verified on a BSD host |
| Windows (MSVC/MinGW) | Partial | core primitives, Winsock sockets, WSAPoll pollset, fd close, and the HTTP/WebSocket clients implemented (ADR 0072); `cfw_server_t`/`cfw_http1_conn_t` and TLS remain stubs returning `CFW_STATUS_UNAVAILABLE`; compile-checked on Windows CI (MSVC `/W4 /WX`, configure+build only, no test run) |

## Compiler and language requirements

- C11 (`-std=c11`, no compiler extensions in public code)
- GCC, Clang, or MSVC-compatible C compiler
- CMake >= 3.25 as the only build system
- No third-party dependencies

## Portability rules

- Platform-specific code lives behind internal boundaries; public headers
  expose only portable types (`intptr_t` handles, fixed-width integers).
- Compile-time OS selection and feature detection go through the
  normalized `CFW_PLATFORM_*`/`CFW_HAVE_*` macros generated by
  `cmake/cfw_platform_detection.cmake` (ADR 0053); raw predefined macros
  are confined to `src/cfw/private/platform_detect.h` and the public
  runtime detector in `platform.c`. Runtime fallbacks exist where
  detection can be ambiguous (e.g. endianness).
- Endianness-sensitive parsing must go through explicit byte-order helpers
  when the network/HTTP layer lands; nothing may assume host order.
- Windows paths, handles, and socket types require their own adapter;
  POSIX-only calls must not leak into shared code.
