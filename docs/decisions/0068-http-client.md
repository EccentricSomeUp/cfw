# ADR 0068: Minimal synchronous HTTP/1.1 client

- Status: Accepted
- Date: 2026-11-27

## Context

ADR 0015 deferred the public socket API "pending a real consumer" and
ADR 0067 landed that API. The motivating consumer is now concrete:
applications need outbound HTTP — health checks, webhook dispatch,
upstream API calls — and the framework already owns every primitive
required (nonblocking sockets, pollset, TLS client role, HTTP
parsing/serialization, chunked decoder).

The design space ranged from a full async client (pooled
connections, streaming requests/responses, redirect handling) to a
minimal one-shot call. The project values auditability and staged
discipline: a pooled async client is a large surface with real
lifecycle and cancellation complexity, while the dominant use case —
"send one request, get one response" — needs none of it.

## Decision

Add `cfw/http_client.h` + `src/cfw/http_client.c`: a minimal
one-shot HTTP/1.1 client built on the public net API.

- `cfw_http_client_request_t` describes one request: host (DNS name
  or numeric literal), port, method, origin-form target, optional
  caller headers, optional body, optional client-role `cfw_tls_ctx_t`,
  a single monotonic `timeout` covering connect + TLS handshake +
  write + read, and `max_head_size`/`max_body_size` caps.
- `cfw_http_client_response_t` owns the raw response head
  (`cfw_buffer_t`) and the fully decoded body (`cfw_buffer_t`);
  `cfw_http_client_response_head` re-parses the stored head into
  `cfw_http_response_head_t` for status/headers access, and
  `cfw_http_client_response_free` releases both.
- One connection per request; `Connection: close` is always sent.
  No keep-alive reuse, redirects, retries, or streaming bodies.
- Internally synchronous but fully nonblocking: an internal pollset
  drives connect completion (`SO_ERROR`), TLS handshake
  (`want_read`/`want_write`), writes, and reads against the single
  deadline. Blocking `getaddrinfo` in `cfw_addr_resolve` is the one
  documented exception — resolve-critical apps should resolve at
  init time.
- Framework-managed headers (`Host`, `User-Agent`, `Content-Length`,
  `Connection`, plus hop-by-hop/framing headers) are generated by the
  client; caller attempts to supply them are rejected with
  `CFW_ERROR_INVALID_ARGUMENT`.
- Response framing reuses the new server-side primitives:
  `cfw_http_response_head_parse` + `cfw_http_response_framing`
  (including the new `CFW_HTTP_BODY_UNTIL_CLOSE` for
  close-delimited bodies), `cfw_http_head_reader_t` for bounded head
  accumulation, and `cfw_http_chunked_decoder_t` for chunked bodies.
  Interim 1xx responses (except 101) are skipped; the stored head is
  always the final response head.
- Error mapping is documented on `cfw_http_client_request`: bad
  request fields or a malformed response head →
  `CFW_ERROR_INVALID_ARGUMENT`; socket/TLS/truncated-body failures →
  `CFW_ERROR_IO`; deadline → `CFW_ERROR_TIMEOUT`; head/body caps →
  `CFW_ERROR_OVERFLOW`; TLS requested without TLS support or no
  socket backend (Windows) → `CFW_ERROR_UNAVAILABLE`.
- TLS is optional: a client-role `cfw_tls_ctx_t` enables HTTPS with
  SNI from `host` and RFC 6125 hostname verification when
  `verify_peer` is set. Without TLS support compiled in,
  `tls_ctx != NULL` yields `CFW_ERROR_UNAVAILABLE`.

## Alternatives considered

- **Async/pooled client API:** rejected for v1 — connection pooling,
  per-request cancellation, and streaming uploads/responses multiply
  the audit surface (lifetime, partial writes, backpressure) without
  a demonstrated need. The synchronous shape can later grow an async
  variant without breaking this API.
- **libcurl-style easy interface:** rejected — third-party
  dependency, against project constraints.
- **Reuse `cfw_http1_conn_t` for the client:** rejected — that type
  is a server-side message reader bound to dispatch semantics;
  client needs response parsing and different framing rules, which
  the new `cfw_http_response_*` primitives provide without contorting
  the server reader.
- **Blocking sockets + `poll` timeout:** rejected — the codebase
  standard is nonblocking I/O with deadline-driven pollset waits;
  mixing models would create a second concurrency contract.

## Consequences

- Outbound HTTP is now possible with ~250 lines of caller code; the
  example `examples/http_client.c` demonstrates the minimal path.
- Response-side parsing primitives (`cfw_http_response_head_parse`,
  `cfw_http_response_framing`, `CFW_HTTP_BODY_UNTIL_CLOSE`,
  `cfw_http_request_head_format`) are new public API in `cfw/http.h`
  and must be maintained under the same stability rules.
- DNS resolution remains blocking and outside the deadline;
  documented as an init-time operation.
- Security audit must cover: header-injection validation, framing
  confusion on responses (TE/CL precedence, interim responses,
  close-delimited bodies), cap enforcement, partial-I/O loops,
  TLS hostname/SNI handling, and fd/pollset lifetime on every error
  path.
